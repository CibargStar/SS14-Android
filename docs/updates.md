# Обновления

APK содержит оригинальный лаунчер, загрузчик, CoreCLR и native-библиотеки. Архивов движков внутри нет. Контент сервера и нужный Android-движок скачиваются при подключении.

## Лаунчер

При запуске и возврате в хаб приложение проверяет APK-каталог своей архитектуры. Повторная проверка ограничена одной минутой. Новый совместимый APK скачивается в фоне; проверяются SHA-256, package ID, version code и сертификат установленного приложения.

**«Установить обновление»** открывает системное подтверждение Android. При первом обновлении Android может запросить разрешение устанавливать приложения из этого источника. **«Продолжить»** откладывает предложение до следующего запуска. Скачанный файл используется повторно после проверки.

Полностью тихая установка обычному APK недоступна: подтверждение Android остаётся. Ручная загрузка через браузер не требуется.

## Движок

Перед каждым подключением оригинальный EngineManager получает актуальный каталог. Для запрошенной версии учитываются официальные redirect и ограничения безопасности.

- Пакета нет — скачивается нужная версия.
- Подпись сборки изменилась при той же версии upstream — скачивается исправленная Android-сборка.
- Сборка прежняя — проверяется SHA-256 установленного файла, повторного скачивания нет.
- Загрузка, хеш или подпись неверны — подключение останавливается, установленный файл и его запись сохраняются.

Новый ZIP проверяется по SHA-256 и Ed25519 и заменяет установленный файл только после проверки. Движок и APK обновляются независимо.

## Публикация

Каталоги находятся в ветке `updates`: `engines.json`, `apk-android-arm64.json`, `apk-android-x64.json`. Адреса закреплены в [update-sources.json](../src/SS14.Android/Assets/update-sources.json).

Для исправления движка выпускаю пакет в новом GitHub-теге и обновляю запись той же версии в каталоге. Номер протокола upstream сохраняется; APK пересобирать не нужно. Изменения лаунчера, загрузчика, runtime или native-библиотек требуют нового APK с прежним сертификатом и большим version code.
