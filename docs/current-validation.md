# Текущее состояние проверок

28 октября 2026. Это запись о ходе разработки; готовая игровая альфа ещё не выпущена.

## На компьютере

- 51 проверка оригинального SS14.Launcher: исходный App/XAML/ViewModels, SQLite, диалоги, результаты/отмена, вложенные окна, pointer click, настройки экрана, подписанные обновления и Android RID.
- 67 проверок размеров экрана и общих настроек процессов: S25 Ultra FHD+ 2340×1080 и QHD+ 3120×1440 дают одинаковую логическую раскладку; масштаб кнопок не зависит от масштаба окон; настройки сохраняются и читаются другим процессом.
- Оригинальный клиент действительно отрисован через native SDL/Mesa offscreen на Linux в обоих разрешениях S25 Ultra. Проверены главное меню, исходное окно Options, новое окно настроек экрана и скрытие управления. Измеренные кнопки находятся внутри экрана и не пересекаются; после скрытия остаётся только UI. Это проверка реального рендера клиента на компьютере, а не исполнение на Samsung.
- 11 проверок data-only автопатча на настоящих архивах 294.0.0: точное восстановление целевого ZIP, неверный исходник/версия/хеш, повреждение, обрыв, отмена и выход за границы. Подписи исходника, патча и результата обязательны.
- Для следующего промежуточного выпуска: 32 проверки стика и 7 проверок через исходный InputManager клиента — владение одним пальцем, восемь направлений, устойчивость около границ, возврат в центр, отпускание и потеря фокуса. Проверен настоящий подписанный пакет 294.0.1 из CI с исходным Content.Client. Геометрия всех элементов совпала с 0.4.0; прочий UI не меняется по указанию пользователя.
- 53 проверки лаунчера включают перенаправление с отозванного исходного бинарника на безопасную подписанную версию и отказ при отозванном конечном движке. Проверка генератора каталога покрывает цепочки, циклы и отсутствующие цели. Старый генератор ошибочно терял такие официальные redirect.
- Проверены подписи установщика движков: корректный пакет принимается, неверный SHA-256/Ed25519 отклоняется до регистрации, временные файлы удаляются, циклы redirect отклоняются. Android-ветка загрузчика не допускает desktop Debug bypass.
- Оригинальные Content.Client/Shared/Shared.Database собраны отдельно от APK. Ресурсы упакованы штатным Content.Packaging.
- `tests/OriginalClient.Smoke` запускает подписанный Android engine через оригинальный SS14.Loader с `--headless`. Клиент доходит до Content.Client.MainMenu.MainScreen, загружает 3200 RSI и 919 текстур без ошибок и завершает процесс командой `hardquit`. Проверка не охватывает графику, нормальное закрытие, сетевой вход или Android.

## В Android-эмуляторе

AOSP API 30, x86_64, программная эмуляция CPU без KVM, SwiftShader. Аппаратного Android-устройства в среде нет; по этому эмулятору нельзя оценивать скорость на телефоне.

- Оригинальный лаунчер установился и отрисовал исходный экран входа и предупреждение early access. Исправлена обязательная тема AppCompat.
- Сенсорный ввод и IME подтверждены в исходном лаунчере: предупреждение закрыто пальцем, в исходный TextBox введён текст экранной клавиатурой. Для эмулятора используется настоящий virtual touch sensor; `adb input tap` на API 30 сообщает другой тип инструмента.
- Приватный GameActivity запускается отдельным процессом с исходным SS14.Loader. Для внутреннего теста rooted эмулятор передаёт ему подписанный engine и отдельно собранный оригинальный контент.
- SDL создал GLES3-контекст и отрисовал штатную заставку SS14. OpenAL и FreeType инициализировались.
- IL-проверка и sandbox включены. Проверены и загружены все три оригинальных игровых модуля. Для ILVerify APK предоставляет PE-метаданные **своего** runtime, включая System.Private.CoreLib из native-части runtime pack.
- На экспериментальном .NET 10 CoreCLR клиент дошёл до исходного главного меню: 3200 RSI, 918 текстур без ошибок, 532 правила стилей. Снимок `artifacts/android-main-menu-without-dialog.png` получен на Android.
- Через исходное меню выполнено подключение к внутреннему серверу 294.0.1: клиент завершил transport/serializer handshake, получил серверную конфигурацию и перешёл в Connected. Полноценный раунд и движение персонажа этой проверкой пока не установлены.
- Пользователь сообщил о входе в меню сервера из хаба на Samsung S25 Ultra через APK 0.3.0. Затем сообщил о слишком крупном интерфейсе; исправления масштаба и скрытия управления подготовлены для 0.4.0. Отзыв пользователя не заменяет проверку всего игрового процесса.
- В следующем тесте пользователь подтвердил вход из хаба и загрузку непосредственно в игру на S25 Ultra. Версия сервера и длительность сессии не записаны; это подтверждение рабочего пути подключения на одном устройстве, а не всех форков и игровых действий.

## Публикация и ограничения

Исходники: https://github.com/CibargStar/SS14-Android. В ветке updates опубликованы постоянный каталог движков и отдельные манифесты APK для ARM64/x64. В актуальных APK встроены 294.0.0 и 294.0.1; также опубликованы подписанные Android-пакеты 289.0.5, 290.0.2, 291.0.2, 292.0.1 и 293.0.1. Успех компиляции не доказывает игровую совместимость каждого форка.

Release android-engines-20261028-2 содержит исправления интерфейса для всех семи версий. Источники каждой версии записаны в android-engine.json; для 294.0.1 используется точный upstream tag cdf8d1258e8f9117b6a74fa80132143350250f16. Исходный submodule 160be31 также содержит более позднюю правку Windows packaging, не игрового кода.

Снимок официального хаба: 180 серверов, 179 успешных ответов, 41 запрошенная версия, 30 сборок после штатных redirect. Это метаданные, а не результат подключения; см. engine-versions-observed.json.

Остаются обязательными: полный игровой цикл, проверка остальных версий/форков, MIDI/native зависимости, остальные мобильные сценарии ввода и жизненного цикла, установка обновления APK от начала до конца на устройстве. SkiaSharp 2.88.9 ещё имеет 4-КБ ELF alignment: совместимость с 16-КБ устройствами не подтверждена.

Повторный CI-прогон 40727671146 успешно собрал 16 точных версий со стиком; девять дополнительных: 275.1.5, 275.2.5, 276.0.4, 277.0.4, 277.2.3, 278.0.2, 283.1.5, 288.0.3, 288.1.2. Компиляция этих пакетов не является подтверждением входа на каждый форк. При обследовании оставшихся версий обнаружен блокирующий NuGet audit для ImageSharp: GHSA-v76p-62qx-wwq2 затрагивает и существующую upstream-зависимость 3.1.12. Исправление требует отдельной проверенной сборки/обновления зависимости; переход на 3.2.0 остановлен требованием лицензионного ключа, audit не отключался. Это открытый вопрос безопасности обработки недоверенных TIFF; новый prerelease не объявляется завершённым безопасным универсальным клиентом.

Обычные временные CI-сборки используют ephemeral-ключ и не являются каналом обновлений. Release-сборки используют постоянный публичный ключ; движки и APK подписываются локально, Actions проверяет и публикует только готовые подписанные файлы. Приватные ключи не передаются в Git/Actions. Первая миграция с временных сборок требует установки подписанного release APK.
