# Участие в разработке

## Ошибка

Используйте [шаблон issue](https://github.com/CibargStar/SS14-Android/issues/new/choose). Нужны версия APK, модель/Android, сервер и движок, точные шаги, ожидаемый результат и лог. Проверяйте воспроизводимость на актуальном тестовом релизе. Не прикладывайте токены и приватные ключи.

## Изменение кода

1. Подготовьте окружение по [docs/building.md](docs/building.md).
2. Меняйте платформенный слой в `src/SS14.Android` либо upstream-код в соответствующем submodule.
3. Для изменений submodule обновите **патч**, сохранив указатель на доступный официальный commit. Новые файлы включайте через `git add -N -- path/to/file` перед `git diff --binary`.
4. Проверьте применение патча к чистому закреплённому upstream и повторное распознавание через `scripts/prepare-*.sh`. При изменении общей логики перенесите её в поддерживаемые version-family patches.
5. Выполните относящиеся к изменению [проверки](docs/testing.md). Для touch/rendering нужны и state-тесты, и настоящий клиент.
6. В PR опишите проблему, итоговое поведение, среду проверки и оставшиеся ограничения.

Не заменяйте оригинальный лаунчер похожей реализацией. Сохраняйте API/протокол каждой версии, проверку подписей, IL-verifier, sandbox и серверные FOV/light-настройки. Успешная компиляция не означает, что сервер протестирован.

## Что хранится в Git

Исходники адаптеров, патчи, скрипты, тесты, workflows, документация и публичные ключи. APK, загруженный контент, native-сборки, артефакты и приватные ключи в main не добавляются. Подписанные бинарники публикуются как release assets. Правила лицензирования зависимостей и атрибуции сохраняются.
